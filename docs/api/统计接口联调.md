# 统计接口联调

## 接口地址

```http
GET http://localhost:8080/api/links/{shortCode}/stats?granularity=day
X-Manage-Token: {manageToken}
```

`shortCode` 和 `manageToken` 使用创建短链接接口返回的值。统计查询不要求链接仍然可跳转，已过期链接仍可查询历史统计，但管理凭证必须匹配。

## 查询参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `from` | 否 | 开始日期，格式 `yyyy-MM-dd` |
| `to` | 否 | 结束日期，格式 `yyyy-MM-dd` |
| `granularity` | 否 | 目前只支持 `day`，默认值为 `day` |

日期规则：

- 两个日期都不传：返回最近 7 个自然日，包含当天。
- 只传 `from`：查询 `from` 起连续 7 天。
- 只传 `to`：查询 `to` 前 6 天至 `to`。
- 同时传入：按闭区间查询，最大 90 天。
- 开始日期晚于结束日期、范围超过 90 天或粒度不是 `day` 时返回 HTTP 400。

## 成功响应

```json
{
  "shortCode": "KkwBVo5J",
  "originalUrl": "https://www.baidu.com",
  "visitCount": 2,
  "lastVisitedAt": "2026-09-16T20:32:24",
  "trendFrom": "2026-09-10",
  "trendTo": "2026-09-16",
  "granularity": "day",
  "pvTrend": [
    {"date": "2026-09-10", "pv": 0},
    {"date": "2026-09-11", "pv": 0},
    {"date": "2026-09-12", "pv": 0},
    {"date": "2026-09-13", "pv": 0},
    {"date": "2026-09-14", "pv": 0},
    {"date": "2026-09-15", "pv": 0},
    {"date": "2026-09-16", "pv": 2}
  ]
}
```

字段说明：

- `visitCount`：Redis 访问增量定时同步到 `short_link` 后的累计值。
- `lastVisitedAt`：累计值最近一次落库时间。
- `pvTrend`：RabbitMQ 访问事件消费后写入 `short_link_daily_stat` 的每日 PV。
- 统计采用最终一致性，刚访问后需要等待消息消费和定时同步完成。

## 联调步骤

1. 先注册并登录，获取 Bearer Access Token。
2. 使用 `POST /api/v1/workspaces/{workspaceId}/links` 创建短链接，保存响应中的 `shortCode` 和 `manageToken`。
3. 访问 `http://localhost:8080/{shortCode}` 两次。
4. 等待 RabbitMQ 主队列消费完成，再请求兼容统计接口。
5. 在响应中确认 `pvTrend` 有 7 项，当前日期的 `pv` 为 2。
6. 使用 `from=2026-09-14&to=2026-09-16` 验证 3 天趋势和零值补齐。
7. 使用错误管理凭证，预期 HTTP 404，错误码为 `LINK_NOT_FOUND`。
8. 使用 `granularity=hour` 或超过 90 天的范围，预期 HTTP 400，错误码为 `INVALID_STATISTICS_RANGE`。

> 说明：当前统计 URL 仍是兼容接口 `/api/links/{shortCode}/stats`。前端迁移到工作空间统计接口后，该兼容接口再下线。

## 故障边界

- RabbitMQ 暂停时，短链接仍应返回 302；访问事件可能等待恢复后再消费。
- Redis 暂停时，跳转降级查询 MySQL；累计访问增量等待消息统计链路处理。
- 统计接口的数据延迟属于预期行为，不用于财务级计费。
