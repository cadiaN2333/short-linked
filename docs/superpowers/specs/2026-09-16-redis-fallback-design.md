# Redis 缓存故障降级设计

## 目标

使 Redis 临时不可用时，短链接跳转仍可回源 MySQL 并正常返回 302。Redis 在本项目中承担性能加速职责，不应成为跳转功能的单点故障。

## 范围

本阶段只处理 Redis 连接或执行命令失败时的降级行为，不加入重试、熔断、限流、缓存预热或负缓存。

## 请求流程

```text
GET /{shortCode}
    ↓
读取 Redis
    ├─ 成功且命中：直接返回缓存中的原始链接
    ├─ 成功但未命中：查询 MySQL，随后尝试回填 Redis
    └─ Redis 失败：记录警告，查询 MySQL
                           ↓
                     有效链接：返回 302
                     不存在或已过期：返回 404
```

## 错误处理

- 仅捕获 Redis 相关异常，例如 `RedisConnectionFailureException`。
- Redis 读取失败视为缓存未命中，继续执行原有的 MySQL 查询和过期判断。
- Redis 写入失败仅记录警告，不影响本次请求返回 MySQL 查询到的有效短链接。
- MySQL 查询或其他编程错误不捕获，维持现有异常处理语义，避免误返回 404 或 302。

## 日志

- Redis 读取失败：警告日志包含短码，不记录原始链接。
- Redis 写入失败：警告日志包含短码，不记录原始链接。
- 保留已有的缓存命中、未命中和写入成功日志。

## 验收标准

- Redis 正常运行时，缓存命中和回填行为保持不变。
- 停止 Redis 容器后，访问已存在且有效的短码仍返回 302。
- Redis 停止时，控制台出现 Redis 降级警告日志。
- 不存在或过期短码在 Redis 停止时仍返回统一的 404 响应。
