# 管理凭证与统计查询接口设计

## 目标

为短链接创建者提供受管理凭证保护的统计查询接口。在尚未引入用户系统时，以随机 `manageToken` 作为创建者持有的管理凭证，避免公开暴露原始链接与访问统计。

## 数据模型

`short_link` 表新增 `manage_token CHAR(32) NOT NULL UNIQUE`：

- 由服务端在创建短链接时生成 32 位随机十六进制字符串。
- 数据库唯一索引作为兜底，防止极低概率的令牌碰撞。
- 历史记录迁移时会补充令牌，但此前创建者没有保存凭证，不能通过新接口查询这些历史记录。

## 创建接口

`POST /api/links` 的响应增加 `manageToken`。

- 只在创建成功时返回一次。
- 不写入应用日志。
- 调用方应妥善保存；遗失后本阶段不提供找回能力。

## 统计查询接口

```text
GET /api/links/{shortCode}/stats
X-Manage-Token: <manageToken>
```

成功响应包含：

- `shortCode`
- `originalUrl`
- `visitCount`
- `lastVisitedAt`

查询条件必须同时匹配短码和管理凭证。短码不存在、凭证缺失或凭证错误时，统一返回现有的 404 响应，避免攻击者借此确认短码是否存在。

接口可以查询已过期短链接，因为过期只禁止跳转，不应抹去创建者的历史统计。

## 一致性

统计查询读取 MySQL 已持久化值，因此受现有 Redis 异步统计同步周期影响，数据最多约一分钟延迟。接口不读取 Redis 中尚未落库的访问增量，保证返回字段语义稳定。

## 组件职责

- `ShortLinkService`：创建时生成令牌；按短码和令牌查询统计。
- `ShortLinkMapper`：提供短码与令牌的联合查询。
- `ShortLinkController`：创建响应返回令牌；新增统计查询接口并读取请求头。
- DTO：创建响应增加令牌字段；统计接口使用独立响应 DTO，避免将令牌返回给查询方。

## 验收标准

- 新创建短链接的响应中有 32 位 `manageToken`。
- 携带正确 `X-Manage-Token` 查询统计，返回原始链接和已落库统计。
- 缺少或使用错误令牌时返回 404。
- 已过期短链接使用正确令牌仍能查询统计。
- 令牌不会出现在普通跳转响应、统计响应或业务日志中。
