# Java 后端实习简历设计

## 1. 目标与范围

### 1.1 目标

围绕 Java 后端实习岗位，设计一页中文简历。版式参考用户提供的简历截图，重点展示教育背景、竞赛/荣誉、两个项目和专业技能，突出可被面试官追问的技术难点与解决思路。

### 1.2 简历结构

```text
个人信息
教育背景
竞赛/荣誉
项目经历
  1. 多租户短链接管理与访问分析平台
  2. 校园生活优惠与探店平台
专业技能
```

个人姓名、学校、专业、联系方式、项目时间和竞赛名称使用占位符，待用户补充后替换。

### 1.3 真实性边界

- 只描述已经完成、能够演示或能够通过代码解释的功能。
- 不虚构用户量、QPS、P99、命中率、订单量等量化指标；如需加入，必须由真实压测或运行记录提供。
- 黑马点评项目只更换业务语境和项目名称，底层技术栈与已完成模块保持一致，不把未实现的支付、微服务或生产监控写成已完成能力。
- 暂未实现的生产级方案（例如 Outbox、DLQ 自动重放、登录限流）放入“后续演进/面试回答”，不写入“已实现功能”。

## 2. 项目一：多租户短链接管理与访问分析平台

### 2.1 项目定位

将当前短链接项目包装为面向团队或个人工作空间的 SaaS 后端，采用 Spring Boot 模块化单体，提供短链接创建、跳转、生命周期管理和访问分析 REST API。

### 2.2 技术栈

Java 17、Spring Boot、Spring MVC、Spring Security、JWT、MyBatis-Plus/MyBatis、MySQL、Flyway、Redis、RabbitMQ、JUnit、Mockito、Maven。

### 2.3 简历重点

建议保留 5～6 条项目要点，覆盖：

1. 工作空间、成员关系和 JWT 鉴权，形成用户身份、成员权限、资源归属三层校验。
2. Base62 随机短码和自定义短码，结合数据库唯一索引处理并发冲突和保留路径。
3. Redis 跳转缓存、状态缓存和负缓存，Redis 异常时回源 MySQL，避免缓存故障阻断 302 跳转。
4. RabbitMQ 异步访问事件、Redis 增量计数和 MySQL 每日聚合统计，消费端按事件 ID 幂等。
5. 定时同步采用 Redis 原子领取、processing Key、失败回补和超时恢复，明确说明当前为 at-least-once 语义。
6. 使用 Flyway、JUnit、Mockito 和 Spring Boot Test 验证迁移、权限、缓存降级、消息发布和统计同步。

### 2.4 禁止写法

- 不写“保证 exactly-once”，应写“消费端幂等 + at-least-once”。
- 不写“支撑百万 QPS”，除非有可复现实验记录。
- 不把已删除的旧创建接口写为当前有效接口。

## 3. 项目二：校园生活优惠与探店平台

### 3.1 场景重构

将黑马点评的业务语境改为校园生活服务：校园餐饮、奶茶、健身、打印店等商家提供优惠券，学生浏览附近商家、领取限量福利、发布生活分享并进行互动。

### 3.2 概念映射

| 原项目概念 | 简历场景 |
| --- | --- |
| 商户/店铺 | 校园餐饮、奶茶、健身、打印等校园商家 |
| 店铺查询 | 校园商家查询、分类筛选和附近商家 |
| 优惠券 | 校园限时优惠券 |
| 秒杀券 | 限量校园福利券 |
| 探店笔记 | 校园生活分享 |
| 关注 Feed | 校园达人动态 |
| 点赞/评论 | 分享内容互动 |
| 用户签到 | 校园打卡 |
| GEO | 校园附近商家定位 |

### 3.3 技术栈

Spring Boot、Spring MVC、MyBatis-Plus、MySQL、Redis、Redisson、JWT、AOP、Maven。若实际项目使用了 Redis Stream、Lua 或其他组件，只在代码和运行记录能够证明时补充。

### 3.4 建议项目要点

1. 使用 Redis 缓存商家详情和热门数据，配合空值缓存、逻辑过期或互斥锁处理缓存穿透、击穿和雪崩风险。
2. 使用 Redis GEO 完成附近校园商家检索，并结合分类条件完成分页查询。
3. 使用 Lua 脚本原子完成限量优惠券资格校验和库存预扣，避免并发超卖。
4. 使用 Redisson 分布式锁、数据库唯一索引和订单状态校验，保证同一用户不能重复下单。
5. 使用异步队列解耦抢券请求和订单落库，降低高峰期数据库瞬时压力。
6. 使用 Redis Set/Sorted Set 实现点赞幂等和关注 Feed 分页，使用 JWT、拦截器和 AOP 统一处理用户上下文。

### 3.5 诚实表述

项目名称和场景可以调整，但面试时应说明“这是本地生活项目的校园场景重构/课程实践项目”，并能回到原始代码解释数据表、接口、Lua 脚本和锁的实现。没有实现的支付、商家后台、微服务拆分等内容不写成已完成。

## 4. 面试追问准备

每条项目经历按“业务问题 → 技术方案 → 一致性/失败边界 → 验证方式”准备回答。

### 4.1 短链接项目

- 为什么使用 302 而不是 301？
- Redis 缓存失效或脏数据时如何保证仍可跳转？
- RabbitMQ 消息重复、不可路由和发布失败如何处理？
- 为什么统计同步不是 exactly-once？如何补偿？
- 工作空间权限如何防止越权？

### 4.2 校园生活项目

- Lua 脚本为什么能避免超卖？
- Redisson 锁和数据库唯一索引各自解决什么问题？
- 缓存击穿、穿透和雪崩分别怎么处理？
- GEO 和普通 SQL 查询如何组合？
- Feed 流为什么使用 Redis，有序分页如何实现？

## 5. 验收标准

- 输出一页中文 Java 后端实习简历初稿。
- 两个项目的技术栈、模块和难点均能与现有代码或真实实践对应。
- 黑马点评项目完成校园场景改写，但不新增虚构指标或未实现能力。
- 每个项目都有可直接用于面试的难点回答。
- 用户补充个人信息后，可直接替换占位符形成最终投递版本。
